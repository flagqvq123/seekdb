# 06 向量检索

## 1. 向量在这个库里长什么样
- 语法：`VECTOR(n)`，n 是固定维度；每表最多一个向量列（赛题限定）。
- 存储：**float32 数组**。写入时把文本 `'[3,4]'` 解析成 f64，再收窄成 f32 保存。
  例：`16777217` 收窄成 f32 就变成 `16777216`，这是**正确语义**（公开用例 vector_float32 要求如此）。
- 校验：必须是方括号包住的数字列表；空列表、NaN、Infinity、超出 f32 范围的数、
  维度不符全部要报错（invalid_vector / dimension_mismatch）。

## 2. 距离：L2_DISTANCE
~~~text
L2_DISTANCE(向量列, '[...]') = sqrt( Σ (a_i - b_i)^2 )
- a_i、b_i 来自**存储后的 f32** 值
- 累加用 f64（避免误差累积），最后开方
- [3,4] 与 [0,0] 的距离 = 5
- 输出允许统一浮点误差（评测容差 1e-5）
~~~

## 3. TopK 语义（最容易被扣分的地方）
1. **先过滤再取 TopK**：`WHERE category='x' ORDER BY distance LIMIT 10` 必须在
   category='x' 的记录集合里算距离、取最近 10 条，不能全表取 10 条再看过滤。
2. **并列规则**：距离完全相等时按**主键升序**排列。
3. **不足 K 条**：返回所有符合条件的记录，不补空行。
4. **空集合**：返回 columns + rows=[]（不能报错）。
5. 普通 `ORDER BY 普通列` 的并列也按主键升序。

## 4. 两条执行路径
| 路径 | 何时用 | 怎么算 | 性能 |
|---|---|---|---|
| 通用逐行 | 任何查询 | 逐行求值 + 收集 + 排序 | 正确但慢 |
| 向量快路径 | 单 ORDER BY 距离 + LIMIT + 字面量查询向量 | 扁平 f32 数组 + 精确扫描 + bounded heap | 快（性能项主力） |

快路径的关键设计：把向量从"每行一个 `Vec<Value>`"变成**一整块连续 f32 数组**
（行主序），扫描时顺序访存、无逐行内存分配、只维护 top-k 小根堆；
有 WHERE 时先用普通列过滤得到候选行下标，再只对候选算距离。

当前单查询的实测数字还没测（等实现接线完）；目标：10k×128 维 **< 300 µs/查询**，
1000 次查询总耗时进百毫秒级。

## 5. 为什么"近似索引"可以降级
赛题原文：
- 性能 benchmark 的查询**默认 exact 模式**，要求精确 TopK；
- ann 模式的验收是"ID 有效、无重复、满足过滤、对应当前记录、Recall@10 ≥ 0.95"。

**精确扫描的 Recall 恒等于 1.0**，天然满足 ann 验收。所以：
- 我们保留 `CREATE VECTOR INDEX` 语句（记录元信息），但**不依赖**它算结果；
- ann 模式直接走精确路径；
- 子智能体做过 HNSW 实验（50k×64：build 52s、recall 0.865），成本高收益低，
  因此降级为可选实现（保留代码但不接入）。

> 这是一次典型的"取舍"：把有限时间投在 66.7% 权重的查询耗时和必过的功能准入上，
> 而不是追求算法花活。
