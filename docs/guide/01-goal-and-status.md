## 2. 赛题要求实现什么（必须支持）

**表结构**：CREATE TABLE；类型 BIGINT / VARCHAR(n) / VECTOR(n)；一个 BIGINT 主键；
每表最多一个向量列。

**数据操作**：INSERT（含多行）、UPDATE、DELETE（按主键或条件）、SELECT。

**查询**：普通列投影、SELECT *、比较运算 `= < <= > >=`、AND、ORDER BY、LIMIT、
`L2_DISTANCE(向量列, '[...]')`、精确 TopK、**带普通列过滤的 TopK**。

**事务**：BEGIN / COMMIT / ROLLBACK；同一时刻最多一个显式事务；事务内读自己的写；
语句失败不能留下部分修改；ROLLBACK 恢复记录、可见集合与向量检索。

**持久化与恢复**：数据写到 /data；正常重启内容一致；进程被强杀后已提交数据不丢、
未提交事务不能部分生效；恢复途中再被强杀仍能恢复。

**明确不需要**：NULL、JOIN、聚合、子查询、ALTER TABLE、外键、嵌套事务、主键更新。
不支持的语句要**返回错误**，不能静默执行成别的意思。

**语义细节**（容易踩坑）：
- VARCHAR(n) 的 n 按 **Unicode 字符数**算（3 字节中文算 1 个）；字符串比较按码点顺序。
- 向量是 float32：输入必须是能表示成有限 float32 的数，拒绝 NaN/Infinity/维度不符/溢出。
- 距离按**存储后的**向量算（例如 16777217 存进去会变成 16777216）。
- 过滤后的 TopK 必须**先过滤再取 K**，不能先全表取 K 再过滤。
- 距离相同按主键升序；普通 ORDER BY 并列也按主键升序。
- 精确模式（default）必须精确；ann 模式只要求 ID 有效、无重复、满足过滤、Recall@10 ≥ 0.95。

## 3. 我们定的技术路线
- **语言 Rust，零第三方 crate**：单二进制、启动快、离线构建不依赖网络（评测时禁止联网，
  依赖必须在构建阶段装好）。手写 JSON 和 SQL 解析，不引库。
- **存储**：磁盘 WAL + 行数据文件 + 内存主键索引 + 有限内存向量热缓存；不允许全量常驻。
- **查询**：通用路径按行流式扫描；向量 TopK 走"扁平数组 + 快速精确扫描"快路径。
- **ANN**：不实现深度优化（性能基准是 exact 模式），ann 模式直接复用精确路径，Recall=1.0。
